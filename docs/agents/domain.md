# Domain docs

Plainspoken is a single-context project.

Before domain work, read `GLOSSARY.md` at the repository root if it exists and applies to the task. Read relevant decisions from `docs/adr/` when that directory contains applicable ADRs. If these files are absent, proceed without treating their absence as a blocker; add a glossary or ADR when the domain language or a lasting architectural decision needs to be recorded.

Use established glossary terms in specs, issue titles and code changes. If a change conflicts with an ADR, call out the conflict and the reason it may need to be revisited.
